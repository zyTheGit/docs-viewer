## 微服务基础

NestJS 内置了几种微服务通信方式的抽象，核心是**消息模式**（基于消息的请求/响应与事件驱动），屏蔽了不同传输层的差异。

### 安装

```bash
npm i --save @nestjs/microservices
```

### 创建微服务

```typescript
// main.ts
import { NestFactory } from '@nestjs/core';
import { Transport, MicroserviceOptions } from '@nestjs/microservices';
import { AppModule } from './app.module';

async function bootstrap() {
  const app = await NestFactory.createMicroservice<MicroserviceOptions>(
    AppModule,
    {
      transport: Transport.TCP,     // 传输层
      options: { host: 'localhost', port: 3001 },
    },
  );
  await app.listen(); // 启动微服务（区别于 HTTP 的 app.listen(3000)）
}
bootstrap();
```

### 处理消息

```typescript
// math.controller.ts
import { Controller } from '@nestjs/common';
import { MessagePattern, EventPattern, Payload } from '@nestjs/microservices';

@Controller()
export class MathController {
  // 消息模式：有请求有响应（类似 RPC）
  @MessagePattern({ cmd: 'sum' })
  accumulate(@Payload() data: number[]): number {
    return data.reduce((a, b) => a + b, 0);
  }

  // 事件模式：发布/订阅，无返回值
  @EventPattern('user_created')
  handleUserCreated(@Payload() data: { name: string; email: string }) {
    console.log('收到事件：', data);
  }
}
```

## 消息模式与事件模式

| 模式 | 装饰器 | 语义 | 是否有响应 |
|------|--------|------|-----------|
| 消息模式 | `@MessagePattern()` | 请求/响应（RPC） | ✅ 有 |
| 事件模式 | `@EventPattern()` | 发布/订阅 | ❌ 无 |

- **消息模式**：调用方发送消息后等待响应，适合查询、计算等需要结果的场景。
- **事件模式**：一方向多个服务广播事件，适合解耦的业务通知（同一事件可被多个 Handler 消费）。
- 两者都支持通配符 /（NestJS 12 中 Kafka 传输层还支持 `RegExp` 模式）：

```typescript
@EventPattern(/^user_.+/)   // Kafka：匹配所有 user_ 开头的事件
handleAnyUserEvent() {}
```

## 客户端代理

调用方通过 `ClientsModule` 注入客户端代理来发送消息：

### 注册客户端

```typescript
// app.module.ts
import { ClientsModule, Transport } from '@nestjs/microservices';

@Module({
  imports: [
    ClientsModule.register([
      {
        name: 'MATH_SERVICE',                    // 注入令牌
        transport: Transport.TCP,
        options: { host: 'localhost', port: 3001 },
      },
    ]),
  ],
})
export class AppModule {}
```

### 发送消息与事件

```typescript
// math.service.ts
import { Inject, Injectable } from '@nestjs/common';
import { ClientProxy } from '@nestjs/microservices';
import { firstValueFrom } from 'rxjs';

@Injectable()
export class MathService {
  constructor(@Inject('MATH_SERVICE') private client: ClientProxy) {}

  // send：消息模式，返回 Observable
  async sum(data: number[]): Promise<number> {
    return firstValueFrom(this.client.send({ cmd: 'sum' }, data));
  }

  // emit：事件模式，发布后即返回
  notifyUserCreated(user: { name: string; email: string }) {
    this.client.emit('user_created', user);
  }
}
```

### 异步注册客户端（结合 Config）

```typescript
ClientsModule.registerAsync([
  {
    name: 'MATH_SERVICE',
    imports: [ConfigModule],
    inject: [ConfigService],
    useFactory: (config: ConfigService) => ({
      transport: Transport.REDIS,
      options: {
        host: config.get('REDIS_HOST'),
        port: config.get('REDIS_PORT'),
      },
    }),
  },
])
```

> 💡 `ClientProxy` 是懒连接的：第一次 `send`/`emit` 时才建立连接。可用 `client.connect()` 显式预热，并利用 `OnModuleInit` 保证启动时连接。

## 传输层详解

NestJS 支持多种传输层，切换只需改 `transport` 与 `options`：

| 传输层 | 枚举值 | 特点 | 适用场景 |
|--------|--------|------|----------|
| TCP | `Transport.TCP` | 默认，内置，无外部依赖 | 单机、学习、简单拆分 |
| Redis | `Transport.REDIS` | 轻量 Pub/Sub | 中小规模、已有 Redis |
| NATS | `Transport.NATS` | 高性能消息总线 | 云原生（Nest 12 改用 `@nats-io/transport-node`） |
| Kafka | `Transport.KAFKA` | 高吞吐、持久化、分区 | 大规模事件流、日志管道 |
| RabbitMQ | `Transport.RMQ` | 成熟 AMQP、消息确认 | 可靠投递、任务分发 |
| gRPC | `Transport.GRPC` | 强类型、高性能 | 语言异构、低延迟内部调用 |

### Kafka 示例

```typescript
// 服务端
@MessagePattern('order_topic')
handleOrder(@Payload() data: Order, @Ctx() ctx: KafkaContext) {
  // 获取分区、offset 等原生信息
  const { partition, offset } = ctx.getMessage();
}

// 客户端
ClientsModule.register([
  {
    name: 'KAFKA_SERVICE',
    transport: Transport.KAFKA,
    options: {
      client: { brokers: ['localhost:9092'] },
      consumer: { groupId: 'order-consumer' },
      producer: { allowAutoTopicCreation: true },
    },
  },
])
```

### gRPC 示例

```protobuf
// proto/hero.proto
syntax = "proto3";

package hero;

service HeroService {
  rpc FindOne (HeroById) returns (Hero);
}

message HeroById { int32 id = 1; }
message Hero { int32 id = 1; string name = 2; }
```

```typescript
// main.ts（服务端）
const app = await NestFactory.createMicroservice(AppModule, {
  transport: Transport.GRPC,
  options: {
    package: 'hero',
    protoPath: join(__dirname, 'hero/hero.proto'),
  },
});

// 服务端 handler（Nest 12+ 配合 GrpcExceptionFilter）
@GrpcMethod('HeroService', 'FindOne')
findOne(data: HeroById): Hero {
  const item = this.heroes.find(({ id }) => id === data.id);
  if (!item) throw new RpcException('NOT_FOUND'); // 映射为 gRPC 状态码
  return item;
}
```

### Redis / RabbitMQ 示例

```typescript
// Redis
{ transport: Transport.REDIS, options: { host: 'localhost', port: 6379 } }

// RabbitMQ（推荐开启 durable 持久化队列）
{
  transport: Transport.RMQ,
  options: {
    urls: ['amqp://localhost:5672'],
    queue: 'orders_queue',
    queueOptions: { durable: true },
    prefetchCount: 10,
    noAck: false, // 手动确认，处理失败可 requeue
  },
}
```

## 混合应用

一个应用同时对外提供 HTTP API 和微服务消息（最常见的生产形态）：

```typescript
// main.ts
import { NestApplication } from '@nestjs/core';

async function bootstrap() {
  const app = await NestFactory.create(AppModule);          // HTTP 应用

  app.connectMicroservice<MicroserviceOptions>({
    transport: Transport.REDIS,
    options: { host: 'localhost', port: 6379 },
  });

  // 可连接多个微服务
  app.connectMicroservice<MicroserviceOptions>({
    transport: Transport.KAFKA,
    options: { client: { brokers: ['localhost:9092'] } },
  });

  await app.startAllMicroservices();  // 启动所有微服务
  await app.listen(3000);             // 同时监听 HTTP
}
bootstrap();
```

## 异常处理与拦截器

### RpcException

微服务抛出 `RpcException`，客户端会以 Observable error 收到：

```typescript
@MessagePattern({ cmd: 'find' })
find(@Payload() id: number) {
  throw new RpcException('Not found');
}

// NestJS 12+：gRPC 专用异常过滤器，状态码不再是 UNKNOWN
@UseFilters(new GrpcExceptionFilter())
@GrpcMethod('HeroService', 'FindOne')
```

### 异常过滤器

```typescript
// rpc-exception.filter.ts
import { Catch, RpcExceptionFilter, ArgumentsHost } from '@nestjs/common';
import { Observable, throwError } from 'rxjs';
import { RpcException } from '@nestjs/microservices';

@Catch(RpcException)
export class ExceptionFilter implements RpcExceptionFilter<RpcException> {
  catch(exception: RpcException, host: ArgumentsHost): Observable<any> {
    return throwError(() => exception.getError());
  }
}
```

### 拦截器与管道

微服务 Handler 同样支持 `@UseInterceptors()`、`@UsePipes()` 和全局管道/守卫（通过 `app.useGlobalPipes()` 等）。

## 可扩展与版本控制

### Message Pattern 元数据

在 ClientProxy 中附加元数据（如租户 ID、trace 信息）：

```typescript
// 发送端
this.client.send({ cmd: 'sum' }, data, { headers: { 'x-trace-id': traceId } });

// 接收端（微服务 handler 的第二个参数）
@MessagePattern({ cmd: 'sum' })
sum(@Payload() data: number[], @Ctx() ctx: any) {
  // ctx 中可取 headers
}
```

### 多个 Handler 同名（版本路由）

```typescript
@MessagePattern({ cmd: 'sum', version: '1' })
sumV1(data: number[]) { /* 旧逻辑 */ }

@MessagePattern({ cmd: 'sum', version: '2' })
sumV2(data: number[]) { /* 新逻辑 */ }
```

## 最佳实践

### 1. 优雅关闭

NestJS 12 起 Express 适配器支持优雅排水；微服务侧确保在 `SIGTERM` 时调用 `app.close()`，让 Kafka/RMQ 完成未处理消息（`enableShutdownHooks()`）。

### 2. 幂等消费

事件模式无法保证"恰好一次"，消费者必须幂等（如用唯一键 upsert 或幂等表）。

### 3. 超时与重试

`ClientProxy.send` 不会自动超时，配合 RxJS：

```typescript
this.client.send({ cmd: 'sum' }, data).pipe(
  timeout(5000),
  retry({ count: 2, delay: 300 }),
  catchError((err) => of({ error: err.message })),
);
```

### 4. 落选方案参考

| 需求 | 推荐 |
|------|------|
| 需要结果且强一致 | 消息模式 + 超时重试 |
| 业务事件广播、最终一致 | 事件模式 + 幂等消费 |
| 大流量日志/流 | Kafka |
| 任务队列、延迟任务 | Bull/BullMQ（见 [16-常用插件](./16-常用插件.md)） |
