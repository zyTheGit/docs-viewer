# 数据库初级指南

> 面向刚接触 NestJS 数据库开发的同学。学完本篇，你能独立完成数据库连接、实体建模和基础增删改查。

---

## 1. 技术选型

NestJS 是框架无关的，主流 ORM 有三种：

| 方案 | 特点 | 推荐场景 |
|---|---|---|
| **TypeORM** | 官方 `@nestjs/typeorm` 集成，装饰器风格 | 传统关系型项目，本系列默认 |
| Prisma | Schema-first，类型推断极强 | 新项目、重类型安全 |
| Sequelize | 老牌、生态成熟 | 遗留项目维护 |

> 本篇以 **TypeORM + PostgreSQL** 为例，MySQL 同理。

```bash
npm install @nestjs/typeorm typeorm pg
```

## 2. 连接数据库

### 2.1 模块化配置（推荐）

```typescript
// app.module.ts
import { Module } from '@nestjs/common';
import { TypeOrmModule } from '@nestjs/typeorm';

@Module({
  imports: [
    TypeOrmModule.forRoot({
      type: 'postgres',
      host: 'localhost',
      port: 5432,
      username: 'postgres',
      password: '123456',
      database: 'nest_demo',
      autoLoadEntities: true,  // 自动加载 Feature 注册的实体
      synchronize: true,       // 开发环境自动同步表结构（生产务必关闭！）
    }),
  ],
})
export class AppModule {}
```

### 2.2 异步配置（读取环境变量）

```typescript
TypeOrmModule.forRootAsync({
  useFactory: (configService: ConfigService) => ({
    type: 'postgres',
    host: configService.get('DB_HOST'),
    port: +configService.get('DB_PORT'),
    username: configService.get('DB_USER'),
    password: configService.get('DB_PASSWORD'),
    database: configService.get('DB_NAME'),
    autoLoadEntities: true,
    synchronize: false,
  }),
  inject: [ConfigService],
})
```

### 2.3 环境变量文件

```bash
# .env
DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=123456
DB_NAME=nest_demo
```

> ⚠️ **新手三大坑：**
> 1. `synchronize: true` 千万不要带到生产环境（会丢失/破坏数据）
> 2. 密码等敏感信息永远不要写死在代码里
> 3. `pg` 版本与 Node 版本不匹配会报 `self signed certificate`，可加 `ssl: false` 排查

## 3. 实体（Entity）

实体是与数据库表一一对应的类。

### 3.1 基础实体

```typescript
// user.entity.ts
import { Entity, Column, PrimaryGeneratedColumn, CreateDateColumn, UpdateDateColumn } from 'typeorm';

@Entity('users')  // 表名，不传则默认为类名小写
export class User {
  @PrimaryGeneratedColumn('uuid')
  id: string;

  @Column({ length: 50, unique: true })
  username: string;

  @Column({ select: false })  // 默认查询不返回密码
  password: string;

  @Column({ default: true })
  isActive: boolean;

  @Column({ nullable: true })
  avatar: string;  // 可空字段

  @CreateDateColumn()
  createdAt: Date;

  @UpdateDateColumn()
  updatedAt: Date;
}
```

### 3.2 常用列装饰器速查

| 装饰器 | 说明 |
|---|---|
| `@PrimaryGeneratedColumn()` | 自增主键 |
| `@PrimaryGeneratedColumn('uuid')` | UUID 主键 |
| `@Column()` | 普通列 |
| `@CreateDateColumn()` | 创建时间，自动填充 |
| `@UpdateDateColumn()` | 更新时间，自动填充 |
| `@VersionColumn()` | 乐观锁版本号 |
| `@Index()` | 索引（可加在类上建联合索引） |
| `@Generated('increment')` | 非主键自增列 |

### 3.3 列选项

```typescript
@Column({
  type: 'varchar',
  length: 100,
  unique: true,
  nullable: false,
  default: 'unknown',
  comment: '用户邮箱',
})
email: string;
```

## 4. 注册实体与 Repository

### 4.1 Feature Module 模式

```typescript
// users.module.ts
import { Module } from '@nestjs/common';
import { TypeOrmModule } from '@nestjs/typeorm';
import { User } from './user.entity';
import { UsersService } from './users.service';
import { UsersController } from './users.controller';

@Module({
  imports: [TypeOrmModule.forFeature([User])],
  controllers: [UsersController],
  providers: [UsersService],
})
export class UsersModule {}
```

### 4.2 注入 Repository

```typescript
// users.service.ts
import { Injectable } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import { Repository } from 'typeorm';
import { User } from './user.entity';

@Injectable()
export class UsersService {
  constructor(
    @InjectRepository(User)
    private readonly usersRepository: Repository<User>,
  ) {}
}
```

## 5. CRUD 五件套

Repository 自带的方法就能覆盖 90% 的初级需求。

### 5.1 创建

```typescript
create(dto: CreateUserDto) {
  const user = this.usersRepository.create(dto);  // 创建实体（不发 SQL）
  return this.usersRepository.save(user);          // 保存（INSERT）
}

// 或者一步到位
save(dto: CreateUserDto) {
  return this.usersRepository.save(dto);
}
```

> `create` 只在内存中构造对象，`save` 才真正写库。用 `create` 可以在保存前做校验/转换。

### 5.2 查询

```typescript
findOne(id: string) {
  return this.usersRepository.findOneBy({ id });
}

// 多条件
findByEmailAndActive(email: string) {
  return this.usersRepository.findOneBy({ email, isActive: true });
}

// 查多个 + 排序 + 分页
findWithPage(page = 1, size = 10) {
  return this.usersRepository.find({
    skip: (page - 1) * size,
    take: size,
    order: { createdAt: 'DESC' },
  });
}
```

> 💡 `findOneBy` 找不到返回 `null`，不会抛错。业务上通常需要手动抛 `NotFoundException`。

### 5.3 更新

```typescript
update(id: string, dto: UpdateUserDto) {
  return this.usersRepository.update(id, dto);
  // 不返回更新后的数据，需要再查一次
}
```

### 5.4 删除

```typescript
remove(id: string) {
  return this.usersRepository.delete(id);
}

// 软删除（实体需加 @DeleteDateColumn）
softDelete(id: string) {
  return this.usersRepository.softDelete(id);
}
```

软删除实体：

```typescript
@DeleteDateColumn()
deletedAt: Date;
```

加了 `@DeleteDateColumn` 后，所有 `find` 自动过滤已删除数据，`softDelete`/`restore` 配套使用。

## 6. 基础关系映射

### 6.1 一对多（用户 → 文章）

```typescript
// user.entity.ts
import { OneToMany } from 'typeorm';
import { Article } from './article.entity';

@OneToMany(() => Article, (article) => article.author)
articles: Article[];
```

```typescript
// article.entity.ts
import { ManyToOne, JoinColumn } from 'typeorm';

@ManyToOne(() => User, (user) => user.articles, { onDelete: 'CASCADE' })
@JoinColumn({ name: 'author_id' })
author: User;

@Column({ nullable: true })
authorId: string;
```

> ⚠️ 关系列（`authorId`）必须手动声明为普通 `@Column`，否则查询外键时需要加载整个关系。

### 6.2 查询时加载关系

```typescript
this.usersRepository.findOne({
  where: { id },
  relations: { articles: true },
});
```

## 7. 种子数据

开发时常需要预置一些数据，简单方式是写一个初始化 Service：

```typescript
// seed.service.ts
@Injectable()
export class SeedService implements OnModuleInit {
  constructor(
    @InjectRepository(User)
    private readonly usersRepository: Repository<User>,
  ) {}

  async onModuleInit() {
    const count = await this.usersRepository.count();
    if (count === 0) {
      await this.usersRepository.save([
        { username: 'admin', password: 'hashed...' },
        { username: 'test', password: 'hashed...' },
      ]);
    }
  }
}
```

## 8. 新手常见报错速查

| 报错 | 原因 | 解决 |
|---|---|---|
| `Repository not found` | 忘记 `forFeature([Entity])` | 在对应 Module 注册实体 |
| `relation "xxx" does not exist` | 关系列名不匹配 | 检查 `@JoinColumn` name |
| `Cannot read properties of null` | `findOneBy` 返回 null 未判空 | 抛 `NotFoundException` |
| `ER_DUP_ENTRY` / `duplicate key` | 唯一索引冲突 | 先查询或捕获 409 |
| 实体修改后表不更新 | `synchronize: false` | 开发时开同步或用迁移 |
| 循环依赖模块报错 | 两个 Module 互相导入 | 用 `forwardRef` 或重新划分模块 |
