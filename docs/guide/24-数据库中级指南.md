# 数据库中级指南

> 面向已掌握基础 CRUD 的开发者。本篇覆盖 QueryBuilder、事务、迁移、关系进阶与查询优化，是日常业务开发的核心技能。

---

## 1. QueryBuilder：复杂查询的利器

Repository 方法写不出的查询，全部交给 QueryBuilder。

### 1.1 基础用法

```typescript
const users = await this.usersRepository
  .createQueryBuilder('user')
  .where('user.isActive = :active', { active: true })
  .andWhere('user.age >= :age', { age: 18 })
  .orderBy('user.createdAt', 'DESC')
  .take(10)
  .getMany();
```

> 💡 参数一律使用 `:param` 绑定，**永远不要字符串拼接**（SQL 注入风险）。

### 1.2 Join 与 getMany / getRawMany

```typescript
// 关联查询
const result = await this.articlesRepository
  .createQueryBuilder('article')
  .leftJoinAndSelect('article.author', 'author')
  .where('article.status = :status', { status: 'published' })
  .getMany();  // 返回实体数组，relations 已填充

// 只取部分字段（返回原始行数据）
const stats = await this.articlesRepository
  .createQueryBuilder('article')
  .select('author.id', 'authorId')
  .addSelect('COUNT(article.id)', 'articleCount')
  .leftJoin('article.author', 'author')
  .groupBy('author.id')
  .getRawMany();
// [{ authorId: '...', articleCount: '12' }, ...]
```

> ⚠️ `getRawMany` 返回的数字是**字符串**（尤其 pg 驱动），需要手动 `Number()` 转换。

### 1.3 分页的标准写法

```typescript
const qb = this.usersRepository
  .createQueryBuilder('user')
  .where('user.isActive = :active', { active: true });

const [items, total] = await qb
  .orderBy('user.createdAt', 'DESC')
  .skip((page - 1) * size)
  .take(size)
  .getManyAndCount();

return { items, total, page, size };
```

### 1.4 子查询

```typescript
const qb = this.usersRepository.createQueryBuilder('user');
const users = await qb
  .where((qb2) => {
    const subQuery = qb2
      .subQuery()
      .select('article.authorId')
      .from(Article, 'article')
      .groupBy('article.authorId')
      .having('COUNT(article.id) >= :n', { n: 10 })
      .getQuery();
    return `user.id IN ${subQuery}`;
  })
  .getMany();
```

## 2. 事务：保证数据一致性

### 2.1 回调式事务（推荐）

```typescript
async transfer(fromId: string, toId: string, amount: number) {
  return this.dataSource.transaction(async (manager) => {
    const from = await manager.findOneBy(User, { id: fromId });
    const to = await manager.findOneBy(User, { id: toId });

    if (!from || !to) throw new NotFoundException('账户不存在');
    if (from.balance < amount) throw new BadRequestException('余额不足');

    await manager.update(User, from.id, { balance: from.balance - amount });
    await manager.update(User, to.id, { balance: to.balance + amount });
    // 任一步抛错，全部回滚
  });
}
```

> `dataSource` 通过 `@InjectDataSource() private dataSource: DataSource` 注入。
> 事务内的查询**必须用事务中的 `manager`**，否则会脱离事务连接。

### 2.2 隔离级别

```typescript
await this.dataSource.transaction('SERIALIZABLE', async (manager) => {
  // 强一致场景，如库存扣减
});
```

常用级别：`READ UNCOMMITTED` < `READ COMMITTED`（pg 默认）< `REPEATABLE READ` < `SERIALIZABLE`。

### 2.3 装饰器式事务（事务包裹业务方法）

```typescript
@Transactional()  // 来自 @nestjs/typeorm-transational 等社区库
async createOrder(dto: CreateOrderDto) { ... }
```

> 也可以基于 CLS（ continuation-local storage）自研，核心是让事务上下文跨层传递。

## 3. 迁移（Migration）

`synchronize: true` 只能用于开发，生产环境必须用迁移管理表结构。

### 3.1 配置数据源文件

```typescript
// data-source.ts（独立于 Nest，供 CLI 使用）
import { DataSource } from 'typeorm';
import 'dotenv/config';

export default new DataSource({
  type: 'postgres',
  host: process.env.DB_HOST,
  port: +process.env.DB_PORT,
  username: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
  entities: ['dist/**/*.entity.js'],
  migrations: ['dist/migrations/*.js'],
});
```

### 3.2 常用命令

```jsonc
// package.json scripts
{
  "migration:generate": "typeorm migration:generate -d data-source.ts",
  "migration:create": "typeorm migration:create",
  "migration:run": "typeorm migration:run -d data-source.ts",
  "migration:revert": "typeorm migration:revert -d data-source.ts"
}
```

```bash
npm run migration:generate -- src/migrations/AddAvatarToUser  # 对比实体生成迁移
npm run migration:run                                        # 执行
npm run migration:revert                                     # 回滚最近一次
```

### 3.3 迁移文件长什么样

```typescript
export class AddAvatarToUser1725800000000 implements MigrationInterface {
  async up(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.addColumn('users', new TableColumn({
      name: 'avatar',
      type: 'varchar',
      isNullable: true,
    }));
  }

  async down(queryRunner: QueryRunner): Promise<void> {
    await queryRunner.dropColumn('users', 'avatar');
  }
}
```

> 📌 **纪律：** 迁移文件一旦提交/在他人环境执行过，禁止再修改；修改表结构永远新增迁移。

## 4. 关系进阶

### 4.1 多对多

```typescript
// article.entity.ts
@ManyToMany(() => Tag, (tag) => tag.articles, { cascade: true })
@JoinTable({ name: 'article_tags' })
tags: Tag[];

// tag.entity.ts
@ManyToMany(() => Article, (article) => article.tags)
articles: Article[];
```

```typescript
// 保存时级联插入 tags
await this.articlesRepository.save({
  title: '标题',
  tags: [{ id: 1 }, { id: 2 }],  // 已存在只需传主键
});
```

### 4.2 级联操作选项

```typescript
@ManyToOne(() => User, (user) => user.articles, {
  onDelete: 'CASCADE',      // 数据库层面：删除用户时删文章
  cascade: true,            // ORM 层面：save 时级联保存
  eager: false,             // true 则每次查主实体自动带出（慎用）
})
```

| 选项 | 层面 | 建议 |
|---|---|---|
| `onDelete` | 数据库 | 强关联必设，明确数据生命周期 |
| `cascade` | ORM | 仅在"子实体完全属于父实体"时使用 |
| `eager` | ORM | 项目早期图省事可用，规模大后改用 `relations` |

### 4.3 N+1 问题

```typescript
// ❌ 坏：查 100 个用户，再循环查文章 = 101 条 SQL
const users = await this.usersRepository.find();
for (const u of users) {
  u.articles = await this.articlesRepository.findBy({ authorId: u.id });
}

// ✅ 好：一次 JOIN 全部查出
const users = await this.usersRepository.find({ relations: { articles: true } });
```

## 5. 查询优化基础

### 5.1 选择性加载字段

```typescript
.find({
  select: { id: true, username: true },
  where: { isActive: true },
})
```

### 5.2 索引

```typescript
@Entity()
@Index('idx_user_active_created', ['isActive', 'createdAt'])
export class User {
  @Column()
  @Index({ unique: true })
  email: string;
}
```

索引原则：
- `where`、`order by`、`join` 涉及的列优先建索引
- 区分度低的列（如性别）单独建索引意义不大
- 联合索引遵循**最左前缀**

### 5.3 用 EXPLAIN 看执行计划

```sql
EXPLAIN ANALYZE
SELECT * FROM users WHERE is_active = true ORDER BY created_at DESC;
```

关注：`Seq Scan`（全表扫描）→ 是否缺索引；`rows` 估算 vs 实际偏差大 → 统计信息过期。

## 6. 数据校验与 DTO 分离

不要直接把 DTO 扔给 `save()`：

```typescript
// ❌ 任何人可以提交 password / role 字段 → 批量赋值漏洞
this.usersRepository.save(dto);

// ✅ 白名单转换
const user = this.usersRepository.create({
  username: dto.username,
  email: dto.email,
});
```

> 配合全局 `ValidationPipe({ whitelist: true, forbidNonWhitelisted: true })` 自动剥离/拒绝多余字段。
